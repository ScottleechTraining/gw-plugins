# GW Research Pipeline

Automated research pipeline: search YouTube for a coaching topic, build a NotebookLM notebook with sources, query for a structured coaching brief, save to vault, ingest into wiki.

**Use cases — this pipeline serves all three:**
1. **Content creation:** Research a coaching topic before running the Content Forge. Deeper research = deeper content.
2. **Film Study prep:** Run before each Film Study to surface evidence, frameworks, and angles that strengthen the session material. NotebookLM is the fuel, not just a search tool.
3. **Course development:** Run before building a new course module to surface the best evidence, frameworks, and teaching points from the knowledge base. Every curriculum build should start here.

## Topic: $ARGUMENTS

The user provides a coaching topic as $ARGUMENTS (e.g., "box squat programming", "contact prep drills", "sprint mechanics for wide receivers").

## Vault Paths

- **Research output:** `D:/Claude Projects/Gridiron Warrior/Research/NotebookLM/`
- **Wiki summaries:** `D:/Claude Projects/Gridiron Warrior/wiki/summaries/`
- **Wiki index:** `D:/Claude Projects/Gridiron Warrior/wiki/index.md`
- **Wiki log:** `D:/Claude Projects/Gridiron Warrior/wiki/log.md`

## Environment

All `nlm` and `yt-dlp` commands require `source ~/.bashrc` first (loads PATH and PYTHONUTF8=1).

## Step 1: Check the Wiki First

Read `D:/Claude Projects/Gridiron Warrior/wiki/index.md`. If a summary page already exists for this topic, tell Scott and ask if he wants to run a fresh research pass anyway or just use what's there.

## Step 2: Gather YouTube Sources

```bash
source ~/.bashrc && PYTHONUTF8=1 yt-dlp --flat-playlist --print "%(webpage_url)s" "ytsearch10:$ARGUMENTS football strength conditioning"
```

Collect all YouTube URLs. If fewer than 5 come back, try a second search with different phrasing.

## Step 3: Create NotebookLM Notebook

```bash
source ~/.bashrc && PYTHONUTF8=1 nlm notebook create "$ARGUMENTS"
```

Parse the notebook ID from the output line: `  ID: [uuid]`

## Step 4: Add YouTube Sources

```bash
source ~/.bashrc && PYTHONUTF8=1 nlm source add [NOTEBOOK_ID] --youtube [URL1] --youtube [URL2] ...
```

Build the command dynamically from the URL list. Up to 50 sources allowed.

## Step 5: Query for Coaching Brief

Wait 10-15 seconds for NotebookLM to process sources, then:

```bash
source ~/.bashrc && PYTHONUTF8=1 nlm notebook query [NOTEBOOK_ID] "You are helping a high school football strength and conditioning coach. Generate a structured coaching brief on $ARGUMENTS. Include: (1) 3-5 core training principles from the sources, (2) 3-5 actionable programming recommendations a coach can implement this week, (3) the 2-3 most common mistakes coaches make with this topic, (4) one quote or specific insight from the sources that would resonate with a football coach. Be direct and specific. No fluff."
```

Parse the answer from the JSON response (`value.answer` field).

## Step 6: Save to Vault

Save as: `D:/Claude Projects/Gridiron Warrior/Research/NotebookLM/[TOPIC-SLUG]-brief.md`

Where TOPIC-SLUG is the topic lowercased with spaces replaced by hyphens.

```markdown
---
date: [YYYY-MM-DD]
notebook_id: [NOTEBOOK_ID]
topic: [TOPIC]
source_count: [NUMBER OF URLS ADDED]
pipeline: gw-research
---

# [TOPIC] — Coaching Brief

[QUERY RESPONSE - cleaned up, no citation brackets]

---
*Generated by GW Research Pipeline | [DATE]*
*NotebookLM Notebook: [TOPIC] — [NOTEBOOK_ID]*
```

[from the brief]

Then:
- Add the new summary to `wiki/index.md` under Summaries → Research Briefs (create that section if it doesn't exist)
- Append to `wiki/log.md`: `## [YYYY-MM-DD] ingest | Research: [TOPIC] — [source count] sources via gw-research`

## Step 7.5: Auto-Create Concept Page Stubs

For each Core Principle from the brief (3-5 typically), check if a matching concept page already exists in `wiki/concepts/`.

For each principle that does NOT have a concept page yet, create a stub:

Path: `wiki/concepts/[principle-slug].md`

```markdown
---
status: stub
created: [YYYY-MM-DD]
type: concept
source_brief: research-[topic-slug]
---

# [Principle Title]

> Stub auto-created during research on **[TOPIC]** on [YYYY-MM-DD]. Expand during weekly lint or when this concept gets used in a Film Study or content pack.

## What it is

[1-2 sentences from the Core Principle paragraph in the brief — the operational definition. Strip "you should..." / "coaches must..." phrasing, lead with what the thing IS.]

## Why it matters

[1-2 sentences from the brief — the consequence of getting this right or wrong. Coach lens.]

## Referenced in

- [[summaries/research-[topic-slug]]] — [YYYY-MM-DD]
```

Then update the parent summary page's **Concepts Touched** section to link the new stubs:

```markdown
## Concepts Touched
- [[concepts/[principle-1-slug]]] (stub — auto-created [DATE])
- [[concepts/[principle-2-slug]]] (stub — auto-created [DATE])
```

If a concept page already exists, link it without the "(stub)" tag and append the current summary to its **Referenced in** section.

**Slug rules:** lowercase, hyphens for spaces, drop articles (a/an/the), max 5 words. Examples:
- "Max effort sprints with full recovery" → `max-effort-sprints`
- "Velocity-based training for in-season power retention" → `velocity-based-training`

## Step 8: Report

Tell Scott:
1. Topic, source count, brief file path
2. Whether this topic already had a wiki page (and if so, what's new vs. what was known)
3. The single most actionable finding in 2-3 sentences
4. Wiki summary file created
5. Concept page stubs created (list with paths) — flag ones to flesh out

## Error Handling

- If `nlm notebook query` returns empty, wait 20 seconds and retry once.
- If fewer than 3 YouTube URLs found, ask Scott before proceeding.
- If vault path doesn't exist, create it.

## After writing the research brief

If this run produced a content pack as part of the chain, the new topic is in `_inbox/`. Run `/gw-queue` to surface it and `/gw-triage` to sort.

If this run only produced a research brief (no content pack), no inbox action needed — the brief lives in `Research/NotebookLM/` for future Content Forge runs.
