# Archive Retrieval

Feeder F6, 2026-09-10. A lesson Scott recorded last spring may be what a coach needs this week. The file does not need to be new for the teaching to be useful. This page says when to look back, how far, how to check that the old lesson is still right, and how to tell new teaching from a repost with a new headline.

The map: `wiki/business/evergreen-teaching-map.md`, at most a handful of hand-curated entries from recurring coaching decisions to exact source passages. Helper: `python -m scripts.gwqueue.evergreen_map lookup "<decision>"` (at most three entries plus the already-covered topics the novelty gate would flag). The helper never opens a source. Reading the passage is the writer's job.

## When to look back

An archive lookup needs a named reason:

- An approved coach-demand signal (F5) points at a problem an older lesson answers.
- A current or recurring coaching decision calls for an existing lesson.
- Fresh research adds context to an older GW explanation and a meaningful new distinction is possible.
- The day's fresh sources support nothing strong, and one specific unresolved coaching decision is worth checking.

Never "find something old because the queue wants three posts." No useful need or no suitable material means fewer or zero ideas. One month is not the same phase for every coach; use the audience's actual or explicitly assumed context, and when timing is uncertain use a genuine recurring decision instead of false calendar urgency. Never resurrect time-limited offers, retired branding, old prices, or old business priorities; check current decisions and offer pages when a business connection matters.

## Budget

At most one named archive question per seed run. Shortlist at most three map entries; open at most two source documents or bounded passages. These reads count against the seed's existing read cap; they do not stack on F2 or F4 budgets. At most one archive-derived angle per run, and it competes under the normal gates and rubric. If source verification and semantic novelty review cannot fit, defer the candidate honestly; uncertainty is never a pass.

## Retrieval and currentness

1. State the current decision and the proposed reader payoff.
2. Resolve the exact source and read the passage at the recorded locator, not the title, not the map's summary.
3. Check `wiki/system/decisions.md`, the relevant entity or offer page, and any `## Recent research` section on the concept page for superseding advice, changed offers, changed terminology, or conflicts. If the check needs more than the budget allows, say verification is incomplete.
4. Apply [claim-boundaries.md](claim-boundaries.md) to every material claim. Scott's practice is his practice, not universal proof. An old study or summary does not carry a current clinical or safety claim.
5. Apply [teaching-readiness.md](teaching-readiness.md): the source must actually hold the promised ingredients.
6. Compare the proposed lesson against known prior outputs (the helper's covered list, then the semantic review) before routing it as new.

A file's modification time proves nothing. A generated wiki update that repeats an old pack is not an independent source. A missing, ambiguous, restricted, or materially contradicted source means "mark for verification and move on," never widen access or open unrelated files.

## Four outcomes

| Outcome | The distinction | Action |
|---|---|---|
| New supported application | The principle answers a materially different decision in a defined context | Normal new-idea route with the receipt below |
| Existing resource already answers it | Same decision, takeaway, and tool already exist | Note the existing resource in the seed; no new angle, no automatic message |
| Explicit reuse or update request | Scott asked to update or repost a specific asset | Scott's existing revision path, not a new unnoticed idea |
| Insufficient distinction | New title, style, or CTA on the same teaching and payoff | No angle; record the duplicate reason |

Audience or format change alone is not enough. Say what decision or application materially changes. A new reference format counts only when it adds a decision aid the earlier asset lacked and the source supports it. Never use a format label to get past novelty review. Never reset skipped, killed, expired, or forged rows, and never create a fresh slug to evade the gate; Scott's recorded rejection reason stands, and a missing reason is not permission. Folder state is not publication: say available, ready, or archived, never "posted," unless posting is recorded.

## Receipt

Archive-derived ideas enter through the normal seed path with F1 origin `seed`; no new origin, no schema change. The seed's Source material line carries the exact source path and locator plus the map id (`[[business/evergreen-teaching-map#em-...]]`). The body sketch and the pack's PULLED FROM THE BRAIN carry five production-only lines:

```
Why now: <the current or recurring decision; "inferred" when not observed>
Teaching source: <exact passage and its real date>
Already covered: <related artifact and the lesson it already delivers>
New contribution: <the material decision or application difference, or "existing resource is enough">
Currentness: <what was checked; unresolved limitations>
```

Never write an old lesson as new research or an old event as this week's. Preserve original attribution. Map capture is provenance, not verification or public-use approval. No bibliography slide, no duplicate master, no new trailing section.

## Map maintenance

Entries carry a `checked` date and a state (`available`, `needs-verification`, `superseded`, `withdrawn`). An old check date is not proof of current support; re-verify when a source or decision changes and record why an entry became superseded without touching the immutable original. Private, client-specific, member-only, or identifiable material never enters the map. The map is refreshed by hand during explicit maintenance; there is no self-updating coverage.
